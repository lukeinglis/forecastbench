# ForecastBench Harness — Status Briefing

**Date:** July 27, 2026
**Prepared for:** Kai sync

---

## Executive Summary

We built a Python backtest harness that replicates the official ForecastBench evaluation pipeline, enabling us to run any LLM forecaster against the benchmark and measure Brier Index scores locally — without waiting for the official leaderboard submission cycle.

**Current best score: 58.8% Brier Index** (hybrid forecaster + calibration), starting from 50% (always-0.5 baseline). The leaderboard target is 60.2% (top-5 LLMs). We've closed roughly 86% of the gap through pipeline alignment, prompt routing fixes, post-hoc calibration, and a hybrid forecaster that routes questions to different reasoning strategies per source.

## What We Built

### Core Harness (16 Python modules, 641 tests)

| Module | Purpose |
|--------|---------|
| `eval.py` | CLI entrypoint — runs forecasters against ForecastBench rounds, handles caching, scoring |
| `fetch_data.py` | Fetches question sets and resolutions from the forecastbench-datasets GitHub repo |
| `score.py` | Brier score/index calculation, difficulty adjustment, Murphy decomposition |
| `baseline_agent.py` | LLM forecaster using Sonnet 4 on Vertex AI — prompt building, parsing, multi-horizon |
| `ensemble.py` | Multi-model ensemble (Sonnet + GPT-4o) with log-odds extremization aggregation |
| `belief_forecaster.py` | BLF-style iterative reasoning forecaster with K=5 multi-trial aggregation |
| `calibrate.py` | Hierarchical Platt scaling — per-source calibration without same-model historical data |
| `analyze.py` | Per-source analysis, calibration curves, bias detection, Murphy decomposition |
| `submit.py` | Submission assembly, validation, GCS upload for official leaderboard |
| `cutoff.py` | Chronological data cutoff enforcement |
| `hybrid_forecaster.py` | Routes questions to belief state vs baseline per source for best-of-both |
| `statistical_baseline.py` | Naive statistical forecasting for timeseries (disabled — hurt scores) |
| `crossval_calibrate.py` | Cross-validation harness for calibration strategy comparison |

### Infrastructure

- **Vertex AI** integration with auto-refreshing ADC credentials (europe-west1 region)
- **Forecast caching** per model slug — avoids redundant API calls across runs
- **Source-aware routing** — different prompt templates and model configs per question source
- **Multi-horizon** single-call extraction matching the official pipeline
- **Results persistence** — JSON results with forecasts, outcomes, and sources for cross-round analysis
- **641 tests** including official parity tests that verify character-level prompt match with the upstream pipeline

### Available Forecaster Agents

```bash
# Dummy (always 0.5 — baseline reference)
uv run python eval.py --agent dummy --round 2026-07-05-llm --raw

# Baseline (Sonnet 4 on Vertex AI)
uv run python eval.py --agent baseline --round 2026-07-05-llm --raw --multi-horizon

# Ensemble (Sonnet + GPT-4o, log-odds extremization)
uv run python eval.py --agent ensemble --round 2026-07-05-llm --raw --multi-horizon

# Belief state (BLF iterative reasoning, K=5 trials — 5x cost)
uv run python eval.py --agent belief --round 2026-07-05-llm --raw --multi-horizon

# Hybrid (belief state for acled/fred/yfinance, baseline for rest — best overall)
uv run python eval.py --agent hybrid --round 2026-07-05-llm --raw --multi-horizon

# With calibration (fit first, then apply)
uv run python eval.py --agent baseline --raw --multi-horizon --fit-calibration
uv run python eval.py --agent baseline --raw --multi-horizon --calibrate

# Per-source model routing (e.g., GPT-4o for timeseries only)
FORECAST_TIMESERIES_MODEL=openai/gpt-4o uv run python eval.py --agent baseline --raw --multi-horizon
```

## What We Tried — Experimental Findings

### What Works

| Technique | Impact | Status |
|-----------|--------|--------|
| **Platt scaling calibration** | +4.8pts average | Active, biggest lever |
| **Hybrid forecaster** | +1.4pts calibrated over baseline-only | Active — belief state for acled/fred/yfinance, baseline for rest |
| **Belief state for fred** | First approach to beat 50% baseline on fred (51.8%) | Active via hybrid routing |
| **Freeze values for market** | +15-22pts on market questions | Active via prompt routing |
| **Extended thinking for events** | +9-12pts on acled/wikipedia | Active (thinking=enabled) |
| **Source-aware routing** | Essential for best config | Active (3 prompt variants + hybrid routing) |
| **temp=0, max_tokens=2000** | +0.5pts | Active, matches official benchmark |
| **Multi-horizon batching** | Better than per-date calling | Active |
| **Sonnet 4.6 > Sonnet 4** | +2pts on fred | Active |
| **GPT-4o for timeseries** | +1pt uncalibrated, +7pts dbnomics specifically | Available |

### What Doesn't Work

| Technique | Result | Lesson |
|-----------|--------|--------|
| **Self-consistency ensemble (N=3)** | Net negative | Disables thinking (Anthropic API constraint: thinking + temperature can't coexist) |
| **Scratchpad for timeseries** | Hurts scores | Base-rate anchoring pushes predictions toward 0.5 |
| **Per-date calling for timeseries** | -5.6pts on fred | Loses temporal context vs multi-horizon batch |
| **Calibration curve transfer** | Doesn't work | Calibration from Sonnet 4 doesn't apply to Sonnet 4.6 |
| **RAG for timeseries** | No value | Questions already have freeze values — RAG adds nothing |
| **Statistical baseline injection** | Hurts scores | Naive "trend continuation" anchoring is wrong for mean-reverting series |
| **Base-rate hints in prompt** | +0.2pts uncalibrated | Redundant with calibration — they correct the same bias |
| **Ensemble (Sonnet + GPT-4o)** | Neutral with calibration | Calibration normalizes away the model diversity benefit |
| **Horizon dampening** | Neutral | Calibration already handles this |

### Root Cause: Timeseries Anti-Correlation

The model makes **systematically wrong directional predictions** on timeseries questions:

- **dbnomics** (temperature): Model thinks "33C is hot, temps will drop" → predicts 49% YES. Actual: 78% YES (seasonal rising trend dominates)
- **fred** (financial): Model thinks "values will keep growing" → predicts 60% YES. Actual: 46% YES (mean reversion)
- **yfinance** (stocks): Model thinks "prices will keep rising" → predicts 62% YES. Actual: 43% YES (corrections)

The prompt provides a freeze value (current data point) that creates anchoring bias in opposite directions per source. Calibration partially corrects this (+4.8pts) but can't fix the underlying prediction ranking.

## Open Threads & Next Steps

### To Close the Gap (58.8% → 60%)

1. **Increase belief state trials** — Currently running K=2 trials, 2 iterations. The BLF paper used K=5 with 3+ iterations and saw larger gains. More trials = better aggregation but ~2.5x more API cost. Could push fred/yfinance above 50% more consistently.

2. **More calibration training data** — Currently fitting on 5 baseline rounds (~10k questions). Running the hybrid forecaster on more rounds would give hybrid-specific calibration data. With 20+ rounds available, more data could push the calibration curve.

3. **Isotonic regression** — Non-linear calibration that could capture patterns Platt scaling misses (e.g., the dbnomics inversion where the model is anti-correlated). Needs sklearn dependency.

4. **dbnomics-specific prompt** — dbnomics (temperature questions) is our worst source. The model systematically predicts the wrong direction. A temperature-aware prompt that accounts for seasonal patterns could help.

5. **Remove freeze value for timeseries** — The freeze value creates anchoring bias. An experiment without it could test whether the model makes better directional predictions from base rate alone.

6. **Model upgrade** — Opus 4.1 scores 61.7% on the leaderboard but isn't available on our Vertex AI project. GPT-5.5 (62.4%) is accessible via OpenAI and could be used for timeseries via the model routing infrastructure.

### Longer-Term Directions

6. **Tournament-mode submission** — The tournament leaderboard allows RAG, fine-tuning, and ensembles. Cassi AI scores 67.9% using sub-question decomposition + multi-model ensemble + meta-LLM analyzer. Our ensemble and belief state infrastructure could support a tournament entry.

7. **Submission pipeline** — `submit.py` can assemble and validate submissions. We need full coverage (all questions in a round forecasted) via `--submit` mode, then GCS upload.

8. **Official comparison** — Run our pipeline on the exact same round that's on the leaderboard and compare per-question scores to verify true parity.

### Infrastructure Improvements

9. **CI/CD** — GitHub Actions pipeline exists (PR #57) but needs updating for the new modules.

10. **Cost tracking** — The ensemble and belief state forecasters are significantly more expensive. Adding per-run cost estimation would help budget API spend.

| Agent | API calls per round | Approx cost per round |
|-------|--------------------|-----------------------|
